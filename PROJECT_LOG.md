# CLAUDE.md — память проекта

Этот файл — единственное место, где хранится контекст проекта между сессиями.
Дополняется по ходу работы без напоминаний от пользователя.

## О проекте

Сайт-визитка + портфолио для художника-витражиста.
Одностраничный лендинг (главная) + отдельные страницы «Обо мне», «Контакты», «Портфолио».

- Название сайта: **ART.OHREY** — арт-студия современного витража
- Автор/художник: **Ирина Павлова**
- Специализация/ниша: современный витраж как самостоятельный предмет интерьера (интерьерные витражные панно/картины для квартир и домов).
  **Важно:** НЕ витражи в храмах, церковных и ритуальных сооружениях, зданиях городской инфраструктуры; НЕ оформление окон/дверей — только самостоятельные интерьерные арт-объекты.
- Позиция по чужому IP (уточнено 2026-09-12): в **текстах** сайта можно упоминать, что Ирина делает витражные интерпретации комиксов/аниме/игр — это её осознанная позиция: фан-арт считается самостоятельным художественным произведением (аналогия — музыкальная аранжировка). Но для **сгенерированных нами изображений-заглушек** портфолио это правило не отменяет — там по-прежнему только собственные придуманные персонажи, без узнаваемых чужих (см. лог решений про портфолио-заглушки).
- Услуги: изготовление современных витражей под заказ + продажа готовых витражей
- Цветовая палитра: холодная (глубокий синий/фиолетовый, «готический»-эстетика, но в современном прочтении — не церковная тематика)
- Тон текстов: дружелюбный и динамичный (неформальный, «на ты» или лёгкое «вы» — уточним при написании текстов)
- Секции главной страницы (актуально): **Обо мне → Услуги → Портфолио → Контакты**. Hero, отзывы, цены, FAQ — пока не делаем, оставляем задел в структуре компонентов на будущее, но на главную не выводим.

## Стек (зафиксирован, не меняется)

- Next.js (App Router) + React + TypeScript, последние стабильные версии
- Серверные компоненты по умолчанию, клиентские — только где обязательно (интерактив: карусель, переключатель темы, формы)
- Tailwind CSS
- shadcn/ui — все интерфейсные примитивы (`npx shadcn@latest add ...`)
- next-themes — светлая/тёмная тема
- next/font — шрифты
- next/image — все изображения, портфолио через SSR
- Контент-данные (отзывы, ссылки, услуги, цены и т.п.) — JSON-файлы в `content/`. Без базы данных.
- Статьи (если появятся) — `.mdx`
- Никакой CMS, никакой авторизации, никаких личных кабинетов, админку не делаем

Alternatives не рассматриваем: Vue, Svelte, Astro, WordPress — решение окончательное.

## Дизайн

- Ничего не изобретаем с нуля. Интерфейсные элементы — только shadcn/ui.
- Готовые секции (hero, features, pricing, testimonials, CTA, FAQ, footer) — из открытых коллекций блоков (Tailark, Magic UI, shadcn.io). Если готового блока нет — собираем из shadcn-компонентов, не выходя за рамки их стиля.
- Светлая/тёмная тема через next-themes. **Тема по умолчанию — тёмная** (`app/layout.tsx`: `defaultTheme="dark"`, `enableSystem={false}`); переключатель в шапке работает независимо от этого.
- Анимации — лёгкие, без перегруза.
- Портфолио — карусель фотографий витражных картин, у каждой фото — своё описание.

## SEO (делаем сразу, не откладываем)

## Инфраструктура и деплой

- Хостинг: VPS на reg.ru, Ubuntu 26.04 LTS — подтверждено по SSH, root-доступ есть. (Первый купленный тариф оказался shared-хостингом с ISPmanager без root — см. в логе решений; сейчас используется второй, настоящий VPS.)
- ⚠️ Сервер маленький: 1 CPU, ~1 ГБ RAM, поэтому Docker-образ **не собирается на сервере** — собирается в GitHub Actions и публикуется в GitHub Container Registry (`ghcr.io/morkelebthennei-hub/site_pavlova`), сервер только скачивает готовый образ. `deploy/vps-setup.sh` заводит 2 ГБ swap-файла для страховки.
- Docker: multi-stage build (`deploy/Dockerfile`), `output: standalone` в `next.config.ts`. `deploy/docker-compose.yml` использует `image:` (не `build:`).
- Nginx как reverse proxy: HTTPS + gzip (`deploy/nginx.conf`, домен art-ohrey.art)
- Let's Encrypt через certbot, автопродление
- GitHub Actions (`.github/workflows/deploy.yml`): `build` (lint+build) → `image` (сборка и push в ghcr.io при пуше в main) → `deploy` (SSH: git pull + docker compose pull/up + healthcheck; пропускается без секретов SSH_HOST/SSH_USER/SSH_PRIVATE_KEY)
- Скрипт первичной настройки VPS — `deploy/vps-setup.sh`: swap, Docker, nginx, certbot, клонирование репозитория

## Правила работы

1. Перед крупной задачей — план (какие файлы создаются/меняются, зависимости). Старт только после «делай».
2. Маленькие итерации, после каждой — видимый результат.
3. После правок — `npm run dev`, проверка что сайт открывается без ошибок. Проблемы чиню сам.
4. Перед коммитом — самопроверка: без мусора и закомментированного кода.
5. Коммиты короткие и по одной задаче.
6. Термины объясняю простым языком, жаргон сразу расшифровываю.
7. Всё, что касается движка/стека, бэкенда, дизайна, доступов и деплоя — сразу фиксирую здесь, в «Лог решений» и в соответствующих разделах выше, без напоминаний. При каждом пуше в GitHub синхронизирую этот файл с `site-project/PROJECT_LOG.md` (копия для репозитория).
